# 模型放置与使用 — 文字驱动语音（GPT-SoVITS）

本文档说明：**用 GPT-SoVITS 训练好的声音模型（或从其他项目导出的模型包），怎么放进本项目、怎么使用。**

## 一、模型放哪里

把整个角色文件夹放到：

```
文字驱动语音\tts_service\models\<角色名>\
```

即：`文字驱动语音\tts_service\models\` 下的**每个子文件夹 = 一个角色/音色**，服务启动时会自动扫描识别，**放进去就能用**（无需重启也能在刷新后识别，个别情况需重启服务）。

> 路径别名：环境变量 `GSV_MODELS_DIR` 可覆盖模型目录；默认就是上面的路径。

## 二、一个角色文件夹必须包含 4 个文件

```
<角色名>\
├── <角色名>.ckpt     GPT 权重（文本 → 语义）  约 150MB
├── <角色名>.pth      SoVITS 权重（语义 → 语音）约 80MB
├── ref.wav           参考音频（该角色一段干净人声，3~10 秒）
└── ref_text.txt      参考音频对应的文字（UTF-8 编码）
```

**文件命名必须和文件夹同名**（例如文件夹 `azhong`，则文件为 `azhong.ckpt`、`azhong.pth`），否则不被识别。

### 兼容旧模型

如果文件夹里没有同名文件，服务会回退为「任意 `.ckpt` + 任意 `.pth`」也能识别（兼容早期版本导出的模型），但推荐按上面标准命名。

### 参考音频要求（ref.wav）

- 时长 **3~10 秒**，越干净越好（无背景音乐、无噪音、无混响）
- 单人说话，语速自然，与该角色实际音色一致
- 内容不限，但要与 `ref_text.txt` 完全对应（逐字一致）
- 格式：wav（服务内自动处理采样率，无需手动转换）

### 参考文本要求（ref_text.txt）

- UTF-8 编码，纯文本
- 内容 = ref.wav 里说的原话（标点、语气词都要对上），示例：
  ```
  大家好，我是阿中，很高兴认识你们。
  ```

## 三、典型来源：GPT-SoVITS 训练输出的模型

用 GPT-SoVITS（官方训练流程）训练完成一个角色后，会产出 4 件套。**把整个角色文件夹复制**到：

```
文字驱动语音\tts_service\models\
```

然后启动/重启 文字驱动语音服务即可。

## 四、怎么确认模型生效

1. 启动服务后访问 http://127.0.0.1:18060/v1/audio/voices
   （应能看到该角色名）
2. 或看启动日志：模型不完整会明确报错，列出缺哪个文件
3. 在对话系统里：设置 → 音频 → 文本转语音音色，下拉应出现该角色

## 六、常见问题

| 现象 | 原因 | 解决 |
|------|------|------|
| 启动报「没有可用的声音模型」 | models 下没有完整角色 | 检查 4 件套是否齐全、命名是否同名 |
| 界面下拉看不到新角色 | 服务未刷新 | 刷新页面或重启服务 |
| 合成出来的声音不对 | ref.wav 与角色不一致 | 换用该角色真实人声做参考 |
| 首次合成慢（10~25 秒） | 该音色模型首次加载 | 正常，加载后常驻秒出 |
| 显存不足 | 多角色同时驻留 | 默认单角色驻留会自动释放；8G 以下显卡自动 CPU 推理 |

## 七、对外接口（供其他系统调用）

- `GET /health` — 健康检查
- `GET /v1/audio/voices` — 音色列表（OpenAI 兼容）
- `POST /v1/audio/speech` — 文字合成语音（OpenAI 兼容协议，body 为 `{model, voice, input}` JSON）
- `POST /api/tts` — 本服务原生合成接口（可选）
